## 2. Corporate/product identity and rights baseline

[n8n](https://n8n.io/) is a workflow-automation platform developed by n8n GmbH, a Berlin company. The legal entity name and corporate structure were **not checked against a filing** as of 2026-10-12. Ownership changed in window: SAP announced a **strategic investment** on 2026-05-12 at a reported USD 5.2bn valuation. The amount was undisclosed, and an SAP minority stake does not make n8n an SAP subsidiary ([joint release reprint](https://www.highlandeurope.com/n8n-valuation-doubles-to-5-2bn-as-sap-makes-strategic-investment-and-plans-to-embed-the-ai-platform-into-joule-studio/); [Tech.eu](https://tech.eu/2026/05/12/n8n-s-valuation-doubles-to-5-2bn-following-sap-strategic-investment/)). No rename or acquisition of the n8n brand was found.

**Licensing as of the window.** The public [n8n-io/n8n](https://github.com/n8n-io/n8n) repository is **source-available, not OSI open source**:
- The [Sustainable Use License v1.0](https://github.com/n8n-io/n8n/blob/master/LICENSE.md) allows use or modification "only for your own internal business purposes or for non-commercial or personal use". Redistribution must be free of charge and non-commercial.
- Files marked `.ee.` fall under the separate **n8n Enterprise License** and need a valid enterprise licence.
- GitHub reports the SPDX ID as `NOASSERTION`.
- Per the repository commit history, `LICENSE.md` last changed on 2024-12-24 and `LICENSE_EE.md` on 2022-08-29. **No licence change occurred in the window.**

Do **not** describe n8n as "open source" in the OSI sense, or assume that hosting it for third parties or embedding it commercially is permitted. Third-party community nodes on npm carry their own licences and **run unsandboxed in the n8n process** (see §4). Cloud plans, Assistant credits and Gateway credits are separate commercial services.

|---|---|---|

Several enterprise controls (`.ee.`, custom roles, telemetry tags) are licence-gated. Running 1.x and 2.x in parallel doubles patch-tracking work for operators. |
| **Community nodes**: queue-mode install bypass (Sep 16) and [OSV malicious npm package](https://osv.dev/vulnerability/MAL-2026-13919) (Aug 12) | Third-party nodes come from npm and n8n validates installs on the normal path | Nodes execute in-process. A Redis-writable attacker could skip every check (fixed). Look-alike npm packages target the ecosystem. Reuse of community nodes needs supply-chain controls. |

**Security volume caveat.** n8n published **153 GitHub advisories in window**: 5 critical, 79 high, 68 medium and 1 low. They came in roughly fortnightly batches, and many were fixed on the 1.x line as well as on 2.x. This is a *disclosure count*. It is not a defect rate and not evidence of exploitation. It may reflect an active disclosure or bug-bounty process as much as code quality, and a comparison with other vendors would need matched denominators. The advisories describe *potential impact under stated conditions*, and most require an authenticated workflow editor or member. For [GHSA-q5f4-99jv-pgg5](https://github.com/advisories/GHSA-q5f4-99jv-pgg5), the CVSS 4.0 vector says `PR:N` while the advisory text requires authentication. This inconsistency should be reported, not resolved by assumption.

## 8. One falsifiable maintainer experiment

**Target:** a small, *authorized* automation in the maintainer's own repositories, for example the scheduled check for new comments on open study issues and posting a digest to a private channel. This study's live Trending `capture` is **disabled under the source-access policy**, and no n8n workflow may be used to scrape GitHub Trending.

**Preregister before the trial.** Freeze one functional unit: *"given a fixed synthetic GitHub repository fixture with 20 issues/comments, produce a correct digest of new comments since timestamp T"*.
- Write **10 hidden acceptance cases** independently: 7 positive, plus 3 negative cases (a deleted comment, a bot comment, a comment from a private fork).
- All 10 cases stay in the denominator.

**Comparators:**
- **A (reuse-first, code):** an existing maintained library (e.g. the `gh` CLI or PyGithub) in a ≤50-line script run by a GitHub Actions cron job.
- **B (reuse-first, visual):** a self-hosted n8n 2.x instance with the built-in GitHub node and the Schedule trigger. Pin an exact patched version, run Community edition only, use **no community nodes**, and disable instance-level MCP.

Both arms use the same token scope (read-only, fixture repo only) and the same fixture.

**Primary endpoint:** hidden cases passed out of 10 for each arm, graded by a reviewer who did not build either arm.

**Secondary endpoints:**
- setup minutes and the minutes to apply each security update over a 30-day observation (count the advisory batches that touch the pinned version);
- review and rework minutes;
- licence-compatibility notes (whether the Sustainable Use License allows the intended use);
- runtime electricity *only if metered*.

**Stop rules:**
- any credential exposure;
- any unpatched critical or high advisory affecting the pinned version for more than 7 days;
- unclear licence fit;
- setup above 4 human-hours for either arm;
- B needing a community node or Cloud-only credits to pass.

Prefer arm A if it passes the same hidden cases with less maintenance. **No trial was executed and no effects were estimated.** A null or negative result for the visual tool is a valid outcome to keep.
