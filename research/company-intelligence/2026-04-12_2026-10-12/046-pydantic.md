## 8. One reproducible, falsifiable pilot for these repositories

**Target:** existing [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study) offline research JSON validation; do **not** install PydanticAI or expose live credentials as a prerequisite.

**Frozen practical external task:** given the **same 12 synthetic, independently authored** input records (6 legitimate, 6 ambiguous/duplicate-key/missing/unsafe cases, stratified and fixed *before implementing the arms*), return a bounded structured decision and fail closed without leaking private input content. All records count, including crashes/refusals. Hidden gold assertions must be authored by a person not implementing either arm.

**Comparator:** (A) existing strict standard-library decoder/validators already in this repository; (B) a **pinned, license-checked** Pydantic Validation implementation with identical input/output/size/privacy rules, only after offline approval. Run on matching Python environments (account for 2.14's Python 3.9 support change), identical tests and measured task review budget. A low-level structural JSON duplicate-key check must remain fail-closed: do not assume Pydantic automatically rejects duplicates.

**Primary success:** independently accepted safe/correct tasks / **all assigned tasks**. **Secondary:** active implementation + review + 30-day update minutes, false accept/reject count, installation/upgrade conflicts, dependency/advisory burden, CI retries and instrumented CPU/CI energy only if actually measured. Avoid synthetic carbon savings.

**Stop/reverse:** if B misses any strict-JSON security rejection, exposes sensitive data, requires unsafe installation, fails license/version validation, or does not improve task acceptance without an unacceptable increase in whole-task maintenance, **retain A**. This is a prospective experiment proposal, **not a result**.

- **New documentary coverage:** 26 event/source records in [CSV](046-pydantic.events.csv) across all seven partial/full calendar segments; these are **purposively selected**, not a census or a probability sample of package users. All important dates have sources; missing historical publication clock or separate deployment date remains blank.
- **Correction (2026-10-15):** Previous draft attributed an August 12 contest report to the May 30 *Hack Monty 2* blog. The actual August 12 document is [Hack Monty 3](https://pydantic.dev/articles/hack-monty-3). Updated event 046-007 to preserve source separation and avoid falsely asserting the May article was edited Aug 12.
- **Independent of author research:** PyPI provides distinct, dated **distribution-metadata** records and supply-chain attestations for exact versions, which are stronger than vendor prose for release chronology, not code-quality/utility proof. GHSA IDs document concrete upstream security risk classes, not our own successful exploits.
- **Open review gaps:** exact ownership/historical parent filings; original immutable page snapshots; every applicable GHSA affected/fixed version and installed dependency; independent contrary **behavioral** tests; service region/edition/retention/legal rights; neutral human factual spot-check and methods approval. No real user adoption, approved experiment, token-to-energy model, or accepted task effect has been measured.
- **Practical no-go:** this repository already has a strict JSON decoder. Adding Pydantic Validation without proving a task-specific advantage can increase transitive dependencies and review cost. In the frozen proposed experiment in section 8, retain the existing implementation if new schema validation fails duplicate keys, input bounds, unknown-state handling, license/security or privacy gates. A reported GA/green CI alone never certifies safe behavior.
- **Issue status:** #113 remains open until all required actual human factual/link, independent methodological and complete source-coverage gates are satisfied. A draft PR can support review; its green jobs are **not** scientific sign-off.

**Maintainer lesson:** require exact PyPI package+version+hash, backward-compatibility migration notes, minimum Python version, latest relevant advisory review and independent adversarial tests before adding even apparently low-risk agent dependencies. Measure human update/rework effort and publish null or failed trials.
