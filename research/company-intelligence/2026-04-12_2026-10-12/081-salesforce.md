## 2. Verified company/product identity and baseline

Salesforce sells a proprietary, hosted CRM platform. Its agent product, **Agentforce**, runs on that platform. The in-window developer story is "headless": platform capabilities offered to outside coding agents and chat assistants as APIs, MCP tools, CLI commands and packaged **skills**. Open-source surface observed: the Salesforce CLI and its plugins (`@salesforce/cli`, `@salesforce/plugin-agent`, Apache-2.0), the DX MCP server (`salesforcecli/mcp`, Apache-2.0, now scheduled for end of life), the skills repository [`forcedotcom/sf-skills`](https://github.com/forcedotcom/sf-skills) (Apache-2.0, "Copyright (c) 2026 Salesforce, Inc."), Slack SDKs (`slackapi/*`, MIT), the Heroku CLI (ISC) and Heroku MCP server (Apache-2.0). The services behind these clients (Agentforce, Data 360, Slack, Heroku, MuleSoft, models such as Koa) are proprietary. An open-source client does not grant rights to the service.

Pre-window baseline (context only, not counted): Agentforce launched less than two years before 2026-06-25, per the Help Agent post. Agent Fabric launched in September 2025 per its April post. The Informatica acquisition predates the window. Agentforce on help.salesforce.com dates from early 2025 per the workforce post.

## 8. One practical, falsifiable change for the maintainer's own repositories

**Repository/component:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study) offline validators and unit tests (`python -m unittest discover -s tests -v`), used as a **synthetic, network-free** task bed. The disabled Trending `capture` command stays disabled.

**Candidate practice (not yet validated):** Before a coding-agent session on this repo, load a small, reviewed, version-pinned **repository skill file** (plain Markdown: CSV ledger rules, event-ID format, closure wording, validator commands) instead of relying on the agent reading `AGENTS.md` and docs ad hoc. This mirrors the skills pattern Salesforce adopted (`sf-skills`, Slack skills plugin), but reuses existing repo text. Nothing is built from scratch, and no Salesforce product, account or paid API is used.

**Treatment/control and frozen comparable task:** Freeze 10 synthetic ledger-maintenance tasks (e.g., add a fixture row with a given date, fix a misordered row, correct a forbidden closure phrase). A person other than the agent operator writes **hidden acceptance tests** and keeps them out of agent context. Arm A: agent with repository access only. Arm B: same, plus the pinned skill file (record its git SHA). Use the same agent, model version, prompt and time box per task, and randomize the order. Accepted-task unit: one patch that passes the hidden tests and `scripts/check_research_artifacts.py`, and that the human reviewer accepts without rework.

**Success and guardrails:** Primary: accepted tasks / all 10 assigned per arm, with refused, failed and timed-out tasks counted. Guardrails: no network access during tasks; no new dependency; full unit suite green; no fabricated URLs or dates in any patch (one fabricated source fails that task); no paid API spend without explicit approval. Commit authorship stays with the maintainer, and no AI contributor attribution is recorded. Measured human work: minutes to write and maintain the skill file, per-task review minutes, rework minutes. No energy or CO2e estimate unless metered.

**Stop/reversal rule:** Keep Arm A if Arm B does not raise accepted tasks by at least 2 of 10, or if skill upkeep exceeds 15 minutes per month of observed changes. Stop immediately if any arm produces a fabricated source or touches the disabled capture path. **No trial executed; no effect estimated.**
