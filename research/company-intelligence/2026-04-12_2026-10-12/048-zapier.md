**Product surface as of the window (vendor-described):** Zaps (deterministic trigger/action workflows), AI by Zapier steps (now including agentic tool calling), the former standalone Agents product, Zapier MCP (hosted MCP server exposing app actions to external AI clients), the Zapier SDK (TypeScript, open beta), Code by Zapier, Tables, Interfaces, Canvas and the Developer Platform (`zapier-platform` CLI/core) for building app integrations.

**Rights are mixed and must be checked per artifact:**

## 6. Conditional 2027–2031 outlook (analyst hypotheses, not company forecasts)

| Testable analyst scenario | Rival cause | Disconfirming observation |
|---|---|---|
| Embedding agentic steps inside deterministic workflows (with per-tool approval) yields more accepted business tasks than free-running agents | Gains come from easier tasks being chosen for workflows, or from human review alone | Matched tasks show equal acceptance and lower cost for a plain scripted pipeline plus a single LLM call |
| Connector artifacts packaged as skill + MCP tool become a portable reuse unit across agent harnesses | Each harness keeps proprietary plugin formats, and ELv2/vendor terms limit portability | The same connector fails to install, or behaves differently, in two harnesses under a frozen task |
| Vendor-maintained connectors reduce user maintenance under upstream API churn | Churn is merely relocated to "action required" migrations users must perform | Count of user-side migration steps per year is equal or higher than for a direct, pinned API client |

## 8. One falsifiable reuse-first maintainer experiment

**Repository/component:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study), notification side-task only. **No** Zapier feature makes the disabled Trending `capture` permissible, and no live GitHub Trending access is involved.

**Frozen task (functional unit):** when a synthetic fixture file in a throwaway test repository changes, post a one-line summary to a test Slack channel (or a mock webhook receiver) and append a row to a test spreadsheet. The task uses 10 fixed synthetic change events (7 valid, 3 malformed that must be rejected), all counted in the denominator. Hidden acceptance assertions are authored by someone other than the implementer: message text, row content, idempotency on replay, rejection of malformed events, and no secret in logs.

**Comparator A (reuse-first, Zapier):** one Zap or a Zapier SDK script using existing pre-built Slack/Sheets actions, with pinned SDK version and recorded plan/terms. **Comparator B (existing-code baseline):** a GitHub Actions workflow using already-maintained official actions/clients with least-privilege tokens. **Comparator C (generate):** an agent-written bespoke script against the raw APIs. Model, prompt budget and reviewer are equal across arms.

**Primary endpoint:** independently accepted events ÷ all 10 events per arm, including failures and timeouts. **Secondary:** human setup + review minutes, lines of new code to maintain, credential scope granted, billed Zapier tasks or CI minutes as reported by each platform, license/terms review time, and a 30-day re-run after dependency updates. Energy is reported only if actually metered. **No CO2 claims from tokens or task counts.**

**Stop rule:** stop an arm if any secret appears in logs, credentials exceed the declared scope, or terms are unclear for the use. Stop the experiment if setup exceeds 2 hours per arm or Zapier billing would exceed the free/beta allowance. Prefer the simplest arm (likely B) if it passes the same hidden tests. **No trial executed, no effects estimated.** A null or negative result must be preserved.
