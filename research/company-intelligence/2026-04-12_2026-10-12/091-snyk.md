## 2. Verified company/product identity and baseline

Snyk sells a developer security platform covering SAST (Snyk Code), SCA (Snyk Open Source), containers, IaC, DAST (Snyk API & Web), secrets, and, since 2025–26, an AI/agent-security line called **Evo**. The open-source surface is mainly the **CLI** ([snyk/cli](https://github.com/snyk/cli), Apache-2.0 LICENSE text), the [agent-scan](https://github.com/snyk/agent-scan) scanner for MCP servers and agent skills (Apache-2.0), [studio-mcp](https://github.com/snyk/studio-mcp) and [studio-recipes](https://github.com/snyk/studio-recipes) (Apache-2.0), and several CLI extensions. The GitHub API reports `NOASSERTION` for the CLI extensions. The vulnerability database, the Evo services and the detection engines are **proprietary SaaS**.

Pre-window baseline (context only, not counted): Evo AI-SPM GA and the agent-security solution launch ([2026-03-23](https://snyk.io/news/snyk-launches-agent-security-solution/)); the AI Security Fabric announcement ([2026-02-03](https://snyk.io/news/snyk-ai-security-fabric/)); the Secure Developer Program launch ([2025-02-25](https://snyk.io/news/snyk-launches-secure-developer-program-deepening-investment-in-open-source/)); the Invariant Labs, Probely and Helios acquisitions (press pages in the sitemap, pre-window); CLI v1.1304.0 (2026-04-09), which introduced `snyk aibom test`; and CLI v1.1303.2 (2026-03-23), which added Agent Red Teaming. **Post-window, excluded:** the [Evo Agentic AppSec launch](https://snyk.io/news/snyk-launches-evo-agentic-appsec/) dated 2026-10-15, CLI v1.1308.1 (2026-10-14), and status incidents after 2026-10-12.

## 8. One practical, falsifiable change for the maintainer's own repositories

**Repository/component:** one maintainer repository with a dependency lockfile, chosen by the maintainer. This study repository (stdlib-only, no `pyproject.toml`) serves as a **negative control**: any dependency finding reported against it is a false positive by construction. The disabled Trending `capture` command stays disabled.

**Candidate practice (not yet validated):** add a **pre-reuse dependency gate** to CI, and record every finding's triage outcome with a written reason, including "disputed upstream advisory". Use reuse first: compare an existing free OSS scanner (OSV-Scanner or `pip-audit`/`npm audit`, already maintained upstream) with the Snyk CLI `snyk test` on the free tier or Secure Developer Program. Do not build a new scanner.

**Treatment/control and frozen comparable task:** freeze the repository at one commit and record exact scanner versions (e.g., Snyk CLI v1.1308.0 and a pinned OSV-Scanner release). **Accepted-task unit:** one finding triaged to a final state, either *fix merged and tests green* or *dismissed with a documented reason accepted by a second reviewer*. Arm A is the OSS scanner. Arm B is the Snyk CLI, manifest scanning only. Snyk Code (source upload) stays **out of scope** unless the maintainer approves code upload terms. Both arms run on the same commit, and findings are pooled and deduplicated by package plus advisory ID before triage. The reviewer is blinded to which tool reported each finding where feasible.

**Success and guardrails:** primary outcomes are (a) true actionable findings per arm, as confirmed by the reviewer, and (b) human triage minutes per accepted finding. Secondary outcomes are the false-positive or disputed share and findings missed by one arm but confirmed in the other. Guardrails: no personal identifiers or tokens in logs; no source-code upload; only free tiers, with no paid plan or API spend unless the maintainer explicitly approves it; no new runtime dependency added to the repository; the full unit suite stays green. The maintainer remains the sole commit author; no AI contributor attribution is added to commits. No carbon or energy figure is reported unless metered.

**Stop/reversal rule:** keep Arm A only if Arm B does not find at least one confirmed actionable issue that Arm A missed across two consecutive monthly runs, or if it adds more than 15 triage minutes per accepted finding on average, or if its terms require uploading code or broader account scopes. Stop immediately on any reported finding against the stdlib-only negative-control repository that a reviewer cannot dismiss in under 5 minutes, or on any credential exposure. **No trial executed; no effect estimated.**
