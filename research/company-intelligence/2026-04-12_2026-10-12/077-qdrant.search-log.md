## Inclusion, deduplication and conflicts

- **Included:** 28 rows (Apr 1, May 5, Jun 4, Jul 4, Aug 4, Sep 5, Oct 5). Every row cites a URL that was fetched as raw text or queried by API. No row relies on a search snippet alone.
- **Duplicate groups:** `077-002` = v1.18.0 release notes and release blog; `077-004` = Edge (PyPI 0.7.0 and Jun 16 blog); `077-007` = one benchmark dispute in three documents (Elastic Jun 24, Qdrant Jul 8, Elastic Jul 13); `077-015` = FineWeb-10B (Qdrant and Vultr posts, same day); `077-019` = v1.19.2 release and GHSA-3gph-6c29-p29v (same fix).
- **Date notes:** blog `datePublished` values carry varying offsets (for example 1.18 at `-0800`, 1.19 at `-0100`); the calendar date shown was used. qdrant-client 1.18.0 and 1.19.0 were uploaded to PyPI about 49 and 16 minutes before their GitHub releases. Private Cloud changelog dates come from version headings; the page's own `datePublished` is a placeholder (`0001-01-01`).
- **Figure conflicts recorded, not resolved:** FineWeb-10B post states ground truth for "120,000 dense, sparse, and filtered queries" and elsewhere "100,000 queries" (Vultr says 120,000); size given as "~25 TiB", "24.47 TB" (Qdrant) and "about 25 TB" (Vultr). Benchmark dispute: Elastic 7x (Jun 24) vs Qdrant 2.1x the other way (Jul 8) vs Elastic "on par", ~56 vs 53–67 QPS (Jul 13).
- **Possible strategy tension, unresolved:** the 2025 public roadmap says Qdrant does not "plan to make a separate serverless product"; the Aug 2026 site adds a "Qdrant Serverless (Coming soon)" product page that also says "Same Qdrant API" and the same engine.
- **Figures confirmed against raw text** (grep of saved page text or API JSON): 4x GPU index builds, NVIDIA T4, 99.95% SLA (cloud post); TurboQuant recall tables and "twice the compression" (1.18 blog); ~11 MB, ~0.1 ms vs ~52 ms (Edge); over 350 attendees (recap); 141 functions (code search); 7x (Elastic Jun 24); 2.1x, 67.2 QPS / 59.5 ms, 32.4 QPS / 122.6 ms (Qdrant Jul 8); about 56 QPS, 0 MB/s and 0 IOPS, "Operation not permitted" (Elastic Jul 13); 1,800 tasks, 1,081→3,158 tasks per GPU-hour, 80.1%→84.2%, 72%→87%, 3,750 (Minima); 24.47 TB, 100,000 / 120,000 queries (FineWeb); five days, 25 TB, 500,000 files (Vultr); ninefold / Turbo4 (1.19 blog); 1.1x / 1.4x (cross-encoders); 34.5M parameters, 199,999,721 training examples (Constella); 30x / 99%, 77x / 94.5%, ~74% (EmbeddingGemma 2); CVSS 8.3, affected range `>= 1.18.0, < 1.19.2` (GHSA via `gh api`); all release dates and PyPI upload times.
