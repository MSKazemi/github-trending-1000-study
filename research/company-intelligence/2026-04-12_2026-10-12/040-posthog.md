## 8. One falsifiable reuse-first maintainer experiment

**Repository/component:** a generic pilot on one of the maintainer's own small repositories with a user-facing CLI or docs site, **or** a synthetic sandbox repo. It must **not** touch the study's disabled Trending `capture` path. No PostHog feature makes unapproved scraping permissible.

**Question:** for a single staged rollout of one small CLI/docs change, does a **reused, self-hostable flag/experiment component** reach the same independently accepted rollout outcome as a **hosted analytics+flags vendor SDK**, at lower maintainer effort and without privacy regressions?

**Comparator A (reuse-first, minimal):** an existing open-source flag library or OpenFeature-compatible in-process provider with a static, version-controlled config file, plus existing logs. No new service. **Comparator B:** PostHog Cloud feature flags + experiments via its MIT/Apache SDKs, pinned version, EU hosting, autocapture and URL capture **disabled**, and model-training opt-out set. Both arms get the same frozen change, the same 2-variant rollout plan and the same pre-registered success metric.

**Functional unit / acceptance test (frozen before trial, authored by someone other than the implementing agent):** (1) a variant is served deterministically to a fixed set of 200 synthetic user IDs within ±2 percentage points of the target split; (2) a kill switch reverts all users within one config change; (3) a synthetic event stream containing a planted secret in a URL fragment and query string is **not** stored or exported; (4) results recompute identically after re-evaluation (the PostHog Jul 24 re-exposure issue as fixture). All attempts count in the denominator, including failed setups.

**Measured cost:** maintainer setup and review minutes, lines of new code, dependency count and licence check, CI minutes, and third-party data egress (yes/no). Energy only if actually metered. **No CO2 claims from tokens.**

**Stop/reversal rule:** stop arm B on any planted-secret capture, unclear data-processing terms or inability to opt out of training. Stop either arm if it fails acceptance tests (1)–(4) twice. Prefer A if it passes all tests with less or equal maintainer time. A null or negative result is reported as such. **No trial executed, no effects estimated.**
