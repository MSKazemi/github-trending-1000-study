## 2. Corporate/product identity and rights baseline

The [terms of service](https://composio.dev/terms) name the operator as **"Sampark Inc, doing business as Composio"**, governed by Delaware law. The terms page shows no last-updated date. Funding coverage ([Entrackr, 2025](https://entrackr.com/news/agentic-ai-startup-composio-raises-25-mn-led-by-lightspeed-9525112)) names co-founders Soham Ganatra and Karan Vaidya, with offices in San Francisco and Bengaluru. No in-window acquisition, rename or parent change was found. Beneficial ownership was **not checked against filings**.

Composio offers a hosted platform. It holds OAuth/API credentials for third-party apps on behalf of developers' end users and exposes "toolkits" (tool definitions) to agents through SDKs, MCP, a CLI and "Tool Router" sessions. The SDK monorepo [ComposioHQ/composio](https://github.com/ComposioHQ/composio) is **MIT** licensed (GitHub license API, checked 2026-10-16; default branch `next`). The PyPI `composio` metadata has an empty license field. The MIT license covers only the **client SDKs/CLI**. The hosted backend, credential vault, toolkit catalog and the internal "Yang" toolkit factory are **not shown to be open source**, and reusing the SDK does not grant any right to the hosted service.

## 6. Conditional 2027–2031 outlook (analyst hypotheses, not company statements)

| Testable scenario | Rival cause | Disconfirming observation |
|---|---|---|
| Hosted credential brokers concentrate risk: one breach exposes many downstream apps (the May incident is one case) | Self-hosted per-app OAuth also leaks through misconfiguration; incidence may be similar per credential | Matched comparisons show no higher per-credential compromise rate for brokered vs self-managed tokens |
| Scoped keys plus per-session tool subsets reduce the harm from prompt injection | Agents still hold broad scopes because narrow scopes break tasks (cf. the Sep 21 over-restrictive bug) | Fixed adversarial tasks show the same unauthorized-action rate with and without session scoping |
| Agent-generated toolkits (Yang) lower integration maintenance cost | Costs shift to human approvers and to downstream breakage | Revert or incident rates per toolkit change are higher for agent-authored PRs than human-authored ones |

## 8. One falsifiable reuse-first maintainer experiment

**Target:** an isolated, authorized sandbox fork of an optional GitHub-automation helper for [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study), never the live study pipeline. The study's live Trending `capture` stays **disabled under the source-access policy**, and no integration platform changes that.

**Frozen task (functional unit):** an agent must (a) read issues from one **synthetic test repository** and (b) post one comment, using a dedicated throwaway GitHub account. Freeze 12 permission cases (6 allowed, 6 forbidden, e.g. writing to a second repository, reading a decoy `.env`/SSH-key file through an upload parameter, or calling a non-GitHub host). All 12 count in the denominator. Hidden assertions are written by someone other than the agent operator.

**Comparator A (reuse official components):** the official GitHub REST client plus a fine-grained PAT or GitHub App scoped to the test repository, with no broker. **Comparator B (reuse broker):** pinned Composio SDK/CLI versions (at or after the CVE-2026-59807 fix) with a scoped project API key, a session restricted to the needed GitHub tools, and `require_approval` where available. Same model, prompts and test fixtures. Record license (MIT SDK; hosted terms reviewed before use), and pin and log exact versions.

**Primary endpoint:** independently accepted tasks with **zero** forbidden actions / all assigned tasks. **Secondary:** forbidden-action false-accept and false-deny counts, setup and review minutes, minutes spent on breaking-change migration over 30 days, credential-rotation time in a simulated revoke drill, CI minutes, and metered energy only if instrumented.

**Cost bound:** at most 2 maintainer-hours setup per arm, a free/test tier only, and no production credentials.

**Stop rule:** stop if any forbidden file read or upload succeeds, if a secret appears in logs or telemetry, if revocation cannot be confirmed upstream, if hosted terms or retention are unclear, or if arm B needs more human minutes than arm A without a better forbidden-action outcome. In that case keep the simpler official-client arm. **No trial executed, no effects estimated.** A null or negative result must be preserved.
