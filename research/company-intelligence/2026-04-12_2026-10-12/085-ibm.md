## 8. One practical, falsifiable change for the maintainer's own repositories

**Repository/component:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study). The run uses offline synthetic tests only. The live Trending `capture` stays disabled under the [source-access decision](../../../docs/SOURCE_ACCESS_DECISION_2026-10-13.md).

**Candidate practice (not yet validated):** an explicit, versioned **agent approval policy**. Read-only tools are auto-approved; file edits, shell commands and MCP/tool calls require approval; per-task file rollback is available. This mirrors the policy IBM describes for Bob V2 (018). It is implemented with the maintainer's **existing** harness permission settings and git worktrees, so it reuses existing tools and adds no new product.

**Comparator:** the maintainer's current default permission configuration in isolated git worktrees, on the same agent, model and pinned versions.

**Frozen task set and functional unit:**
- 10 small, pre-written repository tasks, such as validator rule additions, ledger-schema checks and documentation-consistency fixes. Each has **hidden acceptance tests authored by a human before the trial** and kept out of the agent's context.
- **Functional unit:** one task independently accepted by the hidden tests and a human reviewer. **Every** assigned task counts in the denominator, including refused, failed and timed-out runs.
- Arms are assigned to tasks by a pre-committed allocation, not chosen per task.

**Guardrails:**
- Full unit suite plus `check_research_artifacts.py` must pass for a task to be accepted.
- Any new dependency fails the task unless the reuse gate passes.
- No live GitHub data collection; no credentials in the environment.
- No paid API spend beyond the maintainer's existing subscription without approval.
- Policy file versions are recorded at the start.

**Measured human work:** approval interruptions per task, review minutes per accepted task, rollback uses, rework count and wall-clock time. Energy is recorded only if a hardware meter or RAPL counter is actually available. Otherwise it is reported as **not measured**, and no carbon figure is computed.

**Primary endpoints:**
1. Accepted tasks divided by 10, per arm.
2. Human interruption-plus-review minutes per accepted task.

**Stop/reversal rule:**
- Do not adopt the stricter policy if any of these holds:
  - it accepts 2 or more fewer tasks than the comparator, **or**
  - interruption-plus-review minutes per accepted task rise by more than 30% with no reduction in rejected or unsafe edits, **or**
  - setup takes more than 1 human-hour.
- Stop immediately if any arm modifies files outside its worktree.
- A null or negative result is recorded as such.
- **No trial has been run; no effect is claimed.**
