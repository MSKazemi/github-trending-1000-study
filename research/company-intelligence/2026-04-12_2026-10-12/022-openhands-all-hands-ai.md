**Researcher's conditional interpretation (E0 hypothesis).** If open-core agent vendors keep moving governance features (budgets, secrets, audit, organisation automations) into source-available or proprietary editions while the MIT core changes shape every few months (024, 033), then maintainers who adopt the open core will carry rising re-integration costs (M5). The governance controls they need will also sit behind licence boundaries (M6).

- **Falsifiers:**
  - two or more quarters without a breaking repository, package or interface change in the MIT core;
  - the governance features (budgets, organisation secrets, audit) appearing in MIT repositories;
  - a vendor advisory process that resolves public disclosures such as 015 within a stated window.
- **Rival explanation:** the churn is a one-time consolidation after an early product phase, and the licence split matches common open-core practice without reducing what the MIT core can do for a single maintainer.

### Revised small experiment for this repository (proposed, not performed)

**Reuse-first PR-review check against the existing workflow.**

- **Tasks:** freeze 8 historical PRs from this repository at their merge-parent SHAs, each with a defect that a later commit fixed. Add 2 PRs with no known defect. The defect list is written by a human before any run and kept out of agent context.
- **Arm A:** Agent Canvas `v1.27.1` with `software-agent-sdk` `v1.54.0` and its PR Review automation template, pinned exactly. Run it on a local backend with the Docker conversation runtime and an Agent Profile that has no secrets and no network beyond the model endpoint. Canvas Apps stay disabled.
- **Comparator (arm B):** the existing workflow on the same PRs — the repository's CI (`python3 -m unittest discover -s tests`, `scripts/check_research_artifacts.py`) plus the maintainer's own review, timed.
- **Accepted-task unit:** a review comment that an independent human reviewer, blind to the arm, judges to identify the known defect. False positives are counted on all 10 PRs.
- **Guardrails:**
  - no credentials in the container and no write access to the real repository;
  - review checks must run against the exact head SHA, per the vendor's own feature;
  - record the exact versions;
  - no paid API spend without approval: a locally hosted open-weights model endpoint or a pre-approved budget only.
- **Measurement:** human minutes to set up arm A, human minutes to triage its comments, and defects found per arm. Tokens and energy are not inferred.
- **Stop rule:** stop if arm A needs more than one hour of setup, if it misses more defects than the comparator, or if its triage minutes exceed the comparator's review minutes on 5 of the 10 PRs.
