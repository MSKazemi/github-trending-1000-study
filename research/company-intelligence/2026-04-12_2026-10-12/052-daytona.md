|---|---|---|
| Hosted fork/snapshot/TTL primitives make "disposable workspace + rollback" a default agent-harness pattern | Git worktrees, containers and CI runners already provide cheap rollback for file-only state | Independent tasks show Git-diff/retry matches full snapshots on most accepted tasks, as Daytona's own Sep 18 Terminal-Bench subset suggests |

## 8. One falsifiable reuse-first maintainer experiment

**Target:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study) offline test suite only. No live GitHub Trending capture, which remains **disabled under the source-access policy**. No feature of a sandbox makes unapproved collection permissible.

**Question:** for agent-proposed patches to this repository, does **full-environment snapshot rollback** improve the rate of independently accepted patches compared with the **existing reuse-first baseline** of a fresh `git worktree` plus a local container and `git diff` reset?

**Comparator A (existing tools, no new dependency):** `git worktree add` per attempt, a pinned local Python 3.12 container, and `git checkout -- .` / discard worktree for rollback. **Comparator B:** a Daytona sandbox created from a pinned snapshot via the Apache-2.0 Python SDK, with fork-before-attempt and TTL-bounded deletion. Use the same pinned agent/model, prompt, token budget and attempt limit. Only synthetic fixtures are mounted. No secrets and no repository write tokens are present in either arm.

**Frozen task set (preregister before the run):** 10 bounded tasks drawn from closed historical issues, plus 2 deliberate no-solution tasks. Hidden acceptance tests are authored by a human who did not author the agent prompt, and are kept out of the agent's context. At least 3 tasks must involve state **outside Git** (for example, a generated SQLite fixture or cache directory), because the vendor's own evidence suggests that is the only regime where snapshots help.

**Primary endpoint:** independently accepted tasks / **all** assigned tasks, counting refused, timed-out and failed attempts. **Secondaries:** reviewer minutes, setup and maintenance minutes, wall-clock time, provider bill (as invoiced), sandbox-hours incl. idle/warm time, and metered energy **only if actually instrumented**.

**Guardrails/stop rule:** stop arm B on any credential exposure inside a sandbox, an unpatched advisory affecting the configuration, an unclear licence or terms for test data (AGPL CLI vs Apache SDK), or a cost overrun beyond a pre-set cap. **Adopt nothing** unless B beats A on the primary endpoint by a preregistered margin with no guardrail breach. A tie means keep the simpler, dependency-free worktree baseline. **No trial executed; no effects estimated.**
