## 6. Conditional 2027–2031 outlook (analyst hypotheses, not company statements)

| Testable scenario | Rival explanation | Disconfirming observation |
|---|---|---|
| Production-telemetry context (traces, logs, suspect commits) raises the rate at which agent-written fixes are accepted, compared with agents given only a stack trace | Gains come from the underlying model or from bug easiness, not the telemetry context | Matched-bug trials show equal accepted-fix rates with and without Sentry context, or more reverts |
| Observability vendors become the "trigger and verifier" for coding agents: a failure in production opens a PR, and CI results drive iteration | Teams keep a human in the triage loop because of review cost and liability; agents stay advisory | Seer PR iteration and auto-handoff remain opt-in niche features, or are withdrawn like the Codecov setting |
| Default capture of genAI inputs/outputs causes secret/PII leakage incidents in agent telemetry | Server-side scrubbing and denylist filtering prove sufficient | Independent audits find no secret exposure in default v11 agent traces |
| Source-available (FSL) licensing for agent tooling (MCP server) limits third-party reuse and forks compared with OSI-licensed alternatives | Reuse is mostly via the hosted service anyway, so the license is immaterial | Observable downstream forks/integrations of sentry-mcp match those of OSI-licensed peer MCP servers |

These are **hypotheses**, not evidence of adoption or forecasts issued by Sentry.

## 8. One falsifiable maintainer experiment (reuse-first, not executed)

**Target:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study) offline CLI and tests only. The study's live Trending `capture` stays **disabled** under the source-access decision, and nothing in this experiment touches GitHub Trending or real user data.

**Question:** does structured failure context of the kind an error monitor captures (exception chain, local variables, breadcrumbs, release/commit) raise the rate at which a coding agent's fix is **independently accepted**, compared with the plain CI traceback the repository already produces?

**Frozen task set (preregister before running):** 12 seeded faults, each reverting a known-good change in `trending_study/` that is caught by an existing or hidden test. Hidden regression tests are written by a person other than whoever runs the agent and are kept out of agent context. Include 2 "no-fix-needed" decoys (flaky-looking but correct behaviour) in the denominator.

**Arms:** **A (comparator, reuse existing):** agent receives the issue text plus the raw `unittest` traceback from CI. **B (reuse upstream tool):** same agent and model version, plus a Sentry event for the same failure. The event is captured by the official Python SDK at a pinned version against a self-hosted or free-tier project with `send_default_pii` / `dataCollection` minimised and only synthetic data. B passes the event via the Sentry MCP or as an exported JSON event. No Seer. Optional **C (do not build):** a 30-line home-grown `sys.excepthook` JSON dump with the same fields. If C matches B, the dependency is unnecessary.

**Primary endpoint:** independently accepted fixes ÷ all 12 assigned tasks (refusals, time-outs and decoy "fixes" count as failures or false positives). **Secondary:** reviewer minutes per accepted fix, agent iterations, CI minutes, new test failures, any secret/PII present in captured events (must be zero), setup and 30-day maintenance minutes, and subscription/API cost in currency. Energy is reported only if metered.

**Guardrails and stop rule:** stop if any captured event contains a real credential, email or non-synthetic data. Stop if the SDK/MCP license or self-hosted terms at the pinned version are unclear, or if a known unpatched advisory affects the pinned self-hosted version (check GHSA-rcmw-7mc7-3rj7 and GHSA-jjqr-wqg2-p856 fixed versions). Stop if setup exceeds a pre-set budget (e.g. 4 maintainer hours). **Do not adopt** B unless its accepted-fix rate beats A by a pre-specified margin *and* beats C. A tie or null result is a valid finding and must be preserved. **No trial executed, no effect estimated.**
