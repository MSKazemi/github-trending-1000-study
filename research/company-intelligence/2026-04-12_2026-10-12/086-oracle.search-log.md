**Window:** 2026-04-12 to 2026-10-12 inclusive (UTC dates). **Sources read:** 2026-10-16 (date precision only). **Scope:** the issue's angle, database-proximate enterprise AI, narrowed to OCI Generative AI, Oracle AI Database agents (Select AI), Fusion agent tooling, developer SDKs/drivers and MCP servers, Java/GraalVM releases and AI-contribution policies, security advisories, developer-access changes and contrary coverage. Health (Oracle Health/Cerner), hospitality, retail, financial-services vertical products, data-centre community/energy statements, sponsorships and analyst-ranking releases were screened out on purpose.

## Method

- **Discovery without web search.** The session's web-search budget was nearly exhausted, so no WebSearch query was run. Discovery used: the Oracle news sitemap, OCI release-note service indexes, Oracle security-alert pages, the GitHub API, PyPI JSON, the OpenJDK site, the Wayback Machine CDX API and the Hacker News Algolia API.
- **Reading.** Each ledger `source_url` was fetched with `curl -sL -A 'Mozilla/5.0'` (or read through `gh api` / `gh pr view` for GitHub). Each number, version, date and quoted phrase in the ledger was checked by grepping the saved raw text. No ledger row rests on a model-generated summary or a search snippet. WebFetch was tried once (blogs.oracle.com, HTTP 403) and returned nothing.
- **Identity hygiene.** No email address, name, account handle or other personal identifier was sent in any User-Agent, header, URL or payload. SEC EDGAR / sec.gov was **not contacted**. No account was created, no paywall was bypassed, no product was executed.
- **robots.txt.** Checked with Python `urllib.robotparser` for the generic User-Agent against oracle.com, docs.oracle.com, InfoQ, Ars Technica, TechCrunch, heise, BBC and cnelecar.com: all permitted the pages read. **The Register's robots.txt disallows the generic User-Agent (`User-agent: *` / `Disallow: /`).** One Register article had already been fetched before this check; it is **not used** as evidence anywhere in this screen. Ars Technica's report was used instead.
- **Counts.** Result totals are recorded where an API returned them. Otherwise they are **unknown, not zero**.

## Inaccessible or not used

- **blogs.oracle.com** (database, ai-and-datascience, cloud-infrastructure, java, developers, security, machinelearning RSS feeds and the database index): HTTP 403 to curl and to WebFetch. Oracle engineering-blog posts are therefore **not covered**. This is the largest coverage gap.
- **Reuters** (workforce, Jun 22) and **WSJ** (AI debt, Apr 24): HTTP 401 paywall/bot wall; not read. The BBC report on the same annual-report figures was read instead.
- **app.dealroom.co** (Aug 7 "Oracle bans AI-generated code from OpenJDK" headline, 536 HN points): HTTP 403. The underlying policy page and InfoQ were read instead.
- **The Register** (three PeopleSoft articles, Wisconsin data-centre article): robots.txt disallows generic agents; not used.
- **www.oracle.com/llms.txt** (referenced in Oracle's robots.txt): HTTP 404.
- **docs.oracle.com** URL `/en-us/iaas/releasenotes/generative-ai/` returned 403 and `/en/database/oracle/oracle-database/26/nfcoi/` returned 404; the service-index pages were used instead. The Oracle AI Database 26ai release-update feature guide was not screened.
- **PyPI JSON for the large `oracledb` and `oci` packages:** a bulk script timed out. Per-version JSON was read for oracledb 26.0.0, pyagentspec 26.3.1 and wayflowcore 26.3.0 only.
- **Not attempted:** SEC filings (EDGAR deliberately not contacted), Oracle investor-relations transcripts, My Oracle Support patch notes (login), Gartner/IDC reports, the S&P report itself, the Google/Mandiant threat report, OpenJDK Skara configuration.
