## 2. Corporate/product identity and rights baseline

[Temporal](https://temporal.io/) is a durable-execution platform from **Temporal Technologies Inc.** (name per the [server LICENSE](https://github.com/temporalio/temporal/blob/main/LICENSE) copyright line). The [Sep 14 press release](https://temporal.io/news/temporal-raises-550m-at-a-12-55b-valuation) describes a privately financed, venture-backed company (Series E); no corporate parent was identified, but beneficial ownership and filing-level structure were **not checked**. Headquarters is reported inconsistently by secondary sources (Bellevue vs Seattle, per search-result summaries); unresolved and immaterial here. On Oct 6 the [Oso team joined Temporal](https://temporal.io/blog/oso-security-joins-temporal-accelerate-ai-agent-security); Temporal does not call this an acquisition and discloses no terms. A secondary rewrite attributes to GeekWire a report that a holding company, Tiny, acquired Oso's product; the GeekWire page returned HTTP 403, so this is **unverified**.

**Product boundary:** open-source **Temporal Server** and SDKs versus the proprietary managed **Temporal Cloud** service (Custom Roles, Projects, Billing API, Cloud on Azure, Serverless Workers hosting control). Declared licenses checked via the GitHub API on 2026-10-16: `temporalio/temporal`, `sdk-go`, `sdk-python`, `sdk-rust` (the former `sdk-core` repository name now resolves there), `temporal-worker-controller` and `pi-temporal` are all **MIT**. The server LICENSE also names Uber Technologies, Inc. (2020); this matches the commonly described Cadence lineage, which was not separately verified here. MIT licensing of the server and SDKs does **not** extend to Temporal Cloud's service terms, pricing, data handling or the hosted control plane behind Serverless Workers.

## 6. Conditional 2027–2031 outlook (analyst hypotheses, not company forecasts)

| Testable analyst scenario | Rival cause | Disconfirming observation |
|---|---|---|
| Durable-execution checkpointing of agent tool/model calls reduces lost or duplicated work after crashes in long-running coding agents | Simple idempotent steps, write-once artifacts and a restart script give equal recovery for short tasks | Under matched fault injection, a lightweight checkpoint baseline reaches the same independently accepted completion with less setup and review time |
| Agent-framework vendors converge on an external durable runtime instead of in-framework persistence | Frameworks add their own checkpointers, or the integrations stay in preview | By 2027 the integrations remain experimental, or frameworks deprecate them in favour of native persistence |
| Authorization embedded in execution (the Oso team) yields safer agent actions across retries | Existing IAM/OIDC plus approval gates achieve the same result | No released authorization feature by mid-2027, or blinded tests show no reduction in unauthorized actions |

## 8. One falsifiable reuse-first maintainer experiment

**Target:** an **offline, synthetic** multi-step batch in [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study), e.g. parsing a frozen set of committed synthetic fixture pages and writing write-once outputs. Live Trending `capture` stays **disabled under the source-access hard stop**; no orchestration tool changes that.

**Preregister before trial:** freeze a 20-step synthetic pipeline and a list of 20 fault-injection points (process kill after step *k*, including mid-write). Hidden acceptance checks, authored independently of whoever implements the arms: final outputs are byte-identical to a fault-free reference run; no write-once artifact is overwritten or duplicated; every injected trial is counted in the denominator, including failed or hung ones.

**Comparator A (reuse existing practice):** the repo's existing write-once attempt files plus a small stdlib checkpoint manifest and an idempotent re-run command. **B (reuse upstream library):** the MIT-licensed [Temporal Python SDK](https://github.com/temporalio/sdk-python) with a local development server on localhost, with each step as an Activity. Dependency addition requires prior human review of the exact version, license and provenance, per AGENTS.md. Both arms use the same Python version, fixtures and hardware.

**Primary endpoint:** independently accepted runs / all 20 injected trials. **Secondary:** human setup and review minutes, added LOC and dependency count, CI wall-clock time, upgrade effort, and metered energy **only if actually instrumented**.

**Stop rule:** adopt A and drop B if A passes all 20 trials (no new dependency is justified). Stop B immediately on any overwritten or duplicated write-once artifact, any network access beyond localhost, an unresolved license or provenance question, or setup time exceeding a preregistered budget (e.g. 4 human hours). **No trial executed, no effects estimated.**
