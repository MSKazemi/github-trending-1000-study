## 2. Verified company/product identity and baseline

SAP sells enterprise applications (ERP, finance, HR, procurement, supply chain, CX) and the SAP Business Technology Platform (BTP). In the window, SAP repositioned this as an "Autonomous Enterprise". The **SAP Business AI Platform** (announced 2026-05-12/13) bundles BTP, SAP Business Data Cloud and "AI Foundation" (SAP AI Core / generative AI hub) into context, build and governance layers. The **SAP Autonomous Suite** is the SaaS portfolio re-labelled around Joule Assistants and Joule Agents. **Joule** is the assistant and agent brand: **Joule Work** is the user workspace, **Joule Studio** the build environment, and **SAP AI Agent Hub** (built on SAP LeanIX) the governance inventory.

Developer surfaces in scope include CAP (Cloud Application Programming Model; `@sap/cds` plus Apache-2.0 `@cap-js/*` plugins), ABAP Cloud (ABAP Development Tools, now also for VS Code), UI5/Fiori tooling, SAP Cloud SDK for AI (`SAP/ai-sdk-js`, `SAP/ai-sdk-java`, Apache-2.0), and several Apache-2.0 MCP servers (`cap-js/mcp-server`, `cap-js/mcp`, `UI5/mcp-server`, `SAP/mdk-mcp-server`). The applications, Joule, Joule Studio, AI Core and the platform are **proprietary hosted services**. An Apache-2.0 client, plugin or MCP adapter grants no rights to the services behind it, and the [SAP API Policy](https://help.sap.com/doc/sap-api-policy) still governs API use.

Pre-window baseline (context only, not counted): SAP–Mistral sovereign-AI alliance (2025-11-18); TechEd 2025 developer/agentic BTP announcements (2025-11-04/05); Reltio acquisition agreement (2026-03-27); Joule with SAP Signavio GA (2026-02-10). **Post-window, excluded:** the 2026-10-13 patch day (a maximum-severity OAuth2 SSRF reported by BleepingComputer on 2026-10-14) and the Cloud ERP Private FPS02 release (2026-10-13).

## 8. One practical, falsifiable change for the maintainer's own repositories

**Repository/component:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study) offline unit-test suite and its release tags. The run is **synthetic and network-free** for agents. The disabled Trending `capture` command stays disabled.

**Candidate practice (not yet validated):** the SAP CAP/mbt compromise abused a static npm token, a hijacked developer account that edited a release workflow, and an unsigned commit spoofing an AI-assistant author. The practice under test is a reuse-first **release-integrity gate**: protect workflow files with CODEOWNERS review, require signed commits/tags on the default branch, and run only pinned, existing tooling (GitHub's built-in branch protection, `git verify-commit`, an existing workflow linter such as `actionlint`). The comparator is the current state, meaning no such gate. No new tool is built, and no AI-authorship marker is used as a signal (the owner's policy forbids AI contributor attribution; identity checks rely on signatures and authorised keys only).

**Treatment/control and frozen comparable task:** freeze 10 synthetic change requests on a throwaway fork. Six are benign (docs/test fixes). Four are seeded "malicious-shaped" changes written by a person other than the evaluator and kept from them: an edit to a workflow `run:` step, an unsigned commit with a spoofed author name, a dependency added with an install script, and a release-trigger change on a non-default branch. Arm A: current process. Arm B: the gate. The same reviewer follows the same checklist and time budget in both arms, with order randomised. Accepted-task unit: one change correctly accepted (benign) or blocked (seeded) without rework.

**Success and guardrails:** primary outcome is correctly classified changes out of all 10 per arm. Guardrails: zero real secrets or tokens in the fork (only a planted fake); full unit suite green; no new runtime dependency in the main repository; no paid API spend without approval. Measured human work: setup minutes, per-change review minutes, false-positive blocks of benign changes. No energy or CO2e estimate.

**Stop/reversal rule:** keep Arm A if Arm B blocks no more seeded changes than Arm A, blocks two or more benign changes, or adds more than 5 reviewer minutes per benign change on average. Stop immediately if any real credential is found in the fork. **No trial executed; no effect estimated.**
