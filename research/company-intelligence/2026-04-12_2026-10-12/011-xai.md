## 8. One falsifiable reuse-first maintainer experiment

**Target:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study), offline, using the committed synthetic [parser fixture](../../../tests/fixtures/trending.html). Live Trending `capture` stays **disabled** under the source-access decision.

**Question:** before adopting any coding-agent harness, does a fixed **egress-and-pinning checklist** catch data-exfiltration and model-drift risks that a plain README review misses?

**Preregister:** freeze one small task (add one fail-closed field check to the existing parser plus a test), its hidden acceptance tests written by someone other than the operator, and an egress allow-list of zero hosts except the chosen model endpoint.

- **Comparator A (reuse existing):** the repo's current workflow — no new harness, human edits, existing unit suite.
- **Comparator B (reuse vendor artifact):** Grok Build built from a pinned commit of the Apache-2.0 source (no `curl | bash`), run in a throwaway container with outbound traffic logged, against a pinned dated model slug, on a synthetic copy of the repo with no secrets.
- **Primary endpoint:** hidden-test pass on 5 assigned attempts per arm (all attempts in the denominator). **Guardrail endpoint:** count of outbound destinations other than the model endpoint and bytes uploaded (must be zero for B to continue). **Secondary:** reviewer minutes, setup minutes, invoice cost via `cost_in_usd_ticks`.
- **Cost bound:** ≤ 3 maintainer hours and ≤ USD 5 API spend.
- **Stop rule:** stop B at the first unexpected upload or non-allow-listed host, any need for real credentials, or if A meets acceptance with fewer total minutes. Record a null or negative result as such.

**No trial executed; no effect estimated.**
