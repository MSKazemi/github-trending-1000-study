## 2. Corporate/product identity and rights baseline

[E2B](https://e2b.dev/about) states it was founded in 2023 by Vasek Mlejnsky and Tomas Valenta. It gives its legal name as **FoundryLabs, Inc.** and its locations as San Francisco and Prague. This is vendor-stated and **not filing-verified**. No acquisition or rename of the company was found in the window. The issue's "ownership status requires verification" remains **partly open**: no parent company is asserted anywhere we read. Baseline (pre-window): Series A of $21M announced [Jul 28 2025](https://e2b.dev/resources/series-a). A [Jan 13 2026 control-plane outage postmortem](https://e2b.dev/resources/postmortem-service-disruption-on-jan-13-2026) is also pre-window.

**Product:** a managed cloud API that gives each agent session a **Firecracker microVM with its own kernel**. Shell, filesystem, network, snapshots/forks, desktop and lifecycle controls are exposed through Python/JS SDKs and a CLI. Deployment options are E2B Cloud, Enterprise BYOC (data plane in the customer's AWS/GCP/Azure account, operated by E2B) and, from Sep 2026, **E2B Embed** (single-machine self-hosted).

**Rights:** per the GitHub API (accessed 2026-10-16), [e2b-dev/E2B](https://github.com/e2b-dev/E2B) (SDKs+CLI), [e2b-dev/runtime](https://github.com/e2b-dev/runtime) (orchestrator/control plane/Embed), [code-interpreter](https://github.com/e2b-dev/code-interpreter) and [desktop](https://github.com/e2b-dev/desktop) are **Apache-2.0**. `e2b-dev/infra` now resolves to `e2b-dev/runtime`; when it was renamed was not verified. Apache-2.0 code does not grant rights to the managed cloud, BYOC service terms, SOC 2 reports or hosted Secrets/Volumes. Some runtime features are **feature-gated** (runtime release [2026.30](https://github.com/e2b-dev/runtime/releases/tag/2026.30)), and Embed excludes secrets, volumes, workload identity and bring-your-own-proxy, so "open source" does not mean every cloud feature is self-hostable.

## 8. One falsifiable reuse-first maintainer experiment

**Target:** the offline unit suite of [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study) (`python -m unittest discover -s tests -v`). It is synthetic and needs no network, so **no** live GitHub capture is involved. The study's `capture` command remains disabled under source-access policy, and nothing about E2B changes that.

**Question:** does running coding-agent patch tasks in a reused, pinned isolated sandbox improve *independently accepted* task outcomes or repeatability, compared with the existing local/CI runner, at acceptable maintainer cost?

**Frozen task set:** 10 pre-specified small maintenance tasks, such as adding a validation rule with a negative test, drawn from open issues before the trial. Hidden acceptance tests are written by a human who does not see agent output, and **no-solution tasks stay in the denominator**.

**Comparator A (existing):** GitHub Actions `ubuntu-latest` runner with Python 3.10/3.12 as in current CI, with the agent working in a fresh clone. **B (reuse):** the same agent and model version run each task in an E2B sandbox built from a pinned template (Apache-2.0 SDK, pinned SDK version). Network egress is denied except for the package index, and no secrets are placed inside the sandbox. Optionally **B′** uses self-hosted Embed on a KVM host to test lock-in exit. Same prompts, budgets and timeouts in every arm.

**Primary endpoint:** independently accepted tasks / all assigned tasks. **Repeatability:** each task run 3× per arm, scoring identical pass/fail outcomes and identical dependency lockfile hashes. **Guardrails:** zero secrets in sandbox env/filesystem (checked by scan), zero unexpected egress, all unit tests green. **Cost:** maintainer setup, debugging and review minutes; provider invoice; infra-error retries. Energy is reported only if metered.

**Stop rule:** stop and keep A if B shows no gain in accepted-task rate or repeatability after all 30 runs per arm, if any secret or egress guardrail is breached, if setup plus maintenance exceeds 4 maintainer hours, or if service terms/data handling are unclear. A null result is preserved. **No trial executed; no effect estimated.**
