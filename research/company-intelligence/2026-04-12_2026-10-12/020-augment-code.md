## 2. Corporate/product identity and rights baseline

- **Entity:** Augment Code (the auggie licence names "Augment Computing, Inc."; SiliconANGLE writes "Augment Code Computing Inc."). The exact legal name and corporate structure were **not** checked against a registry.
- **Products in window:** IDE extensions (VS Code, JetBrains), the **Auggie CLI**, the **Context Engine**, **Cosmos** (agent platform across the SDLC, later branded "software factory"), **Prism** model routing and **Cosmos Advisor**.
- **Ownership change (end of window):** on 2026-10-08 Augment said it had "agreed to sell" Cosmos, Auggie CLI, the Code Context Engine and related technology to **Harness**. Harness's post the same day says it "has acquired select Augment Code assets". This is an **asset** transaction: neither source says the whole company was bought, and neither discloses terms, closing date or what happens to existing Augment contracts (rows CI2026-020-003, 020-E27).
- **Licences (via `gh api`, 2026-10-16):** [augmentcode/auggie](https://github.com/augmentcode/auggie) is **not OSS**. `LICENSE.md` is a "Custom Proprietary License for Augment CLI" that requires an active subscription (GitHub reports `NOASSERTION`). Other org repos carry MIT (e.g. `auggie-zed-extension`, `context-connectors`, `augment-agent`, `review-pr`), Apache-2.0 (`rtk`, `sandbox-infra`) or no detected licence (`augment-swebench-agent`, `augment.vim`: `NOASSERTION`). A public repo is not permission to reuse the hosted service, the context index or Cosmos.
- **Supply-chain notes:** the auggie-v2 release notes say macOS and Windows binaries are **unsigned**, with only Linux SHA256SUMS published (020-E07, 020-E16, 020-E21). The repo shows **no GitHub security advisories** (empty `security-advisories` response).

## 6. M1–M7 study relevance

| Construct | Prospective measurement, not inferred conclusion |
|---|---|
| **M1** workflow chronology | Date each workflow change (review agents, verifier, human-only merge) separately from adoption. A release is not uptake |
| **M2** accepted quality/effort | Independently authored acceptance tests for fixed tasks; count failures and abstentions. Vendor revert rates are not external quality evidence |
| **M3** visibility | Blog/benchmark attention ≠ use. No star or traffic inference |
| **M4** verified third-party reuse | Requires consented downstream evidence. Changing vendor ownership makes long-run reuse claims fragile |
| **M5** reuse vs new build | Compare existing tools (proprietary CLI under subscription vs OSS alternatives) with licence, signing and continuity checks |
| **M6** lifecycle cost | Reviewer minutes, billed inference, CI and upgrade churn (several builds/day). **No token-to-kWh or CO2e conversion** |
| **M7** ethical/safe adoption | Symlink/trust-boundary tests (GhostApproval), sensitive-file prompts, workspace-trust hooks and human-merge policy as observable controls |

## 7. One falsifiable reuse-first maintainer experiment (proposed, not executed)

**Question:** does a repo-specific `AGENTS.md`, curated from **existing** project docs (reuse-first), improve independently accepted agent patches over no context file, as Augment's Apr 22 post claims, or does it give only cost changes with no quality gain, as its Apr 30 post found?

- **Target:** [`MSKazemi/github-trending-1000-study`](https://github.com/MSKazemi/github-trending-1000-study) offline code and synthetic fixtures only; no network capture (Trending `capture` remains disabled).
- **Design:** before any run, a person other than the implementing agent freezes 8 small test-fix tasks with hidden acceptance tests. Arms: **A** no AGENTS.md, **B** the current `AGENTS.md`, **C** a ≤150-line file distilled from existing docs with links. Same pinned agent/model version, budget and environment; 3 runs per task-arm. Every refusal, timeout and failure stays in the denominator.
- **Primary endpoint:** fraction of runs that pass the independent hidden tests (with uncertainty). **Secondary:** reviewer-repair minutes, billed cost if actually metered, files touched outside the task scope, and any write through a planted symlink fixture (must be 0; GhostApproval-style safety check).
- **Disconfirming result:** no difference in accepted-task rate between A, B and C (the Apr 30 null pattern), or C worse than A. Preserve that result rather than promoting the context file.
- **Stop/rollback:** any write outside the workspace or through a symlink, any secret read, or cost per accepted task that gets worse without a quality gain.

## 8. Limitations

- **Mostly vendor sources:** 26 of 28 rows come from Augment's own pages (blog, changelog, GitHub releases). Independent evidence is limited to Wiz (security, with an Infosecurity Magazine cross-check) and transaction reporting that relays company statements.
- **Unstable URLs:** two Cosmos launch URLs now redirect to an undated product page. One body was recovered from an archive and the other (020-E11) is unverifiable. The changelog is a rolling page, so entries may disappear.
- **Dates:** publication date ≠ shipping date. Many posts carry later "last updated" stamps (often Jun 18), which can mean post-publication edits.
- **Not done:** no installation, benchmark rerun, security reproduction, legal-registry check, closing verification, or check of whether the symlink issue was fixed. Five web searches were run and further planned queries were **not executed** (see [search log](020-augment-code.search-log.md)).
- **No inference** of adoption, market share, productivity or emissions. An AI assistant drafting and checking its own report is not an independent reviewer.
