## 2. Verified company/product identity and baseline

MongoDB develops the MongoDB document database. The self-managed products are Community Edition (Server Side Public License, SSPL) and the commercial Enterprise Advanced. **MongoDB Atlas** is the proprietary managed cloud service. Atlas also offers full-text search and vector search, run by a separate `mongot` process. MongoDB also sells **Voyage AI** embedding and reranking models as a hosted API, and in-window it added agent-facing services: the hosted Atlas Managed MCP Server and Atlas Agent Engine. The drivers (for example pymongo and the Node `mongodb` package) and the MCP server are Apache-2.0 (per the PyPI/npm metadata and the GitHub API). The server and `mongot` source is SSPL v1, which is not an OSI-approved open-source licence.

Pre-window baseline (context only, not counted): the Voyage AI acquisition; a leadership transition announced 2025-11-03, after which CJ Desai became CEO; MongoDB Agent Skills, introduced 2026-03-31 (mongodb/agent-skills releases v1.0.0 and v1.1.0 date from March 2026); the May 2025 lawsuit against FerretDB; automated embedding for Community Edition, posted 2026-01-15. **Post-window, excluded:** the MongoDB 9.0 GitHub tags r9.0.2 and r9.0.4 (created 2026-10-14), MCP server v3.1.0 (2026-10-15), pymongo 4.19.0 (2026-10-14), the Hibernate ORM GA blog (2026-10-13) and the 9.0.4 security patch (release notes date it Oct 13).

## 8. One practical, falsifiable change for the maintainer's own repositories

**Repository/component:** [github-trending-1000-study](https://github.com/MSKazemi/github-trending-1000-study) offline research artifacts (the `research/company-intelligence/` ledgers and the `trending_study` validators), run as a **synthetic, network-free** task. The disabled Trending `capture` command stays disabled.

**Candidate practice (not yet validated):** Answer evidence-lookup questions over the committed ledgers with a **reused** local retrieval component instead of ad-hoc `grep`. Reuse first: the comparator is plain `grep`/`csv` filtering, which is already available. The treatment is an existing local hybrid retrieval setup: MongoDB Community Edition with self-managed Search/Vector Search, SSPL, run locally and used only as a tool, not redistributed. The licence must be reviewed before any use, and no Atlas or hosted Voyage AI is used because they require an account and paid API calls. If the SSPL review fails, a permissively licensed local alternative may replace the treatment. Do not build a new retrieval engine.

**Treatment/control and frozen comparable task:** A person other than the operator freezes 20 lookup questions, for example "which ledger rows cite an NVD record for a driver?" or "which events share a duplicate group?". That person also writes the hidden answer sets, which stay out of the operator's and any agent's context. Arm A uses grep/csv. Arm B uses the local retrieval index built from the same pinned commit. Same operator, randomized question order, same 10-minute cap per question. Accepted-task unit: a question whose returned row IDs exactly match the hidden answer set.

**Success and guardrails:** Primary: accepted answers / 20 (time-outs and refusals count as failures). Guardrails: no network calls during the task (container `--network none`), no new dependency committed to the repo, no data leaves the machine, and the full unit suite stays green. Measured human work: setup minutes, per-question minutes and index-maintenance minutes after one ledger update. Report no energy or CO2e figure unless metered. No paid API spend without approval. Commit authorship stays with the maintainer.

**Stop/reversal rule:** Keep Arm A if Arm B does not raise the accepted rate by at least 3 of 20 questions. Also keep Arm A if Arm B adds more than 30 setup minutes, needs re-indexing work that exceeds the time it saves, or its licence review is not cleared. **No trial executed; no effect estimated.**
