## Hypotheses to test in this repo, not conclusions

1. Re-estimate coding-agent prevalence on a **prospectively documented observable repository frame** with frozen definition, explicit missing/ambiguous traces, repository ID deduplication and report coverage/sensitivity. Do **not** claim this sample generalizes to all GitHub developers or Trending exposure.
2. On opt-in accepted software tasks, test changes in **functional success, human review/repair time, maintenance and reported developer experience** (SPACE dimensions), not commit volume or lines written alone. Track failed/abandoned tasks and unknown outcomes in the denominator.
3. On any changed source version, preserve the original DOI/arXiv ID/version, sample size, estimate, exposure window and codebook separately; use a preregistered sensitivity analysis rather than retrospectively selecting the most impressive version.
