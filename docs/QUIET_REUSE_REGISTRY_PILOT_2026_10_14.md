# Issue #15: pinned registry-slice sampling pilot (2026-10-14)

**Research status: bounded external source record + reproducible lead selection, NOT a completed scientific cohort.** This is an extension of the existing [quiet-reuse frame](QUIET_REUSE_FRAME_SELECTION_2026_10.md), not a competing Trending collector. No Trending capture was made or access restriction bypassed.

## Source, population and numerator/denominator

- Source: public [crates.io package index](https://github.com/rust-lang/crates.io-index), commit [`9b349b77adb46425be15e386ef38f31061be3ca9`](https://github.com/rust-lang/crates.io-index/commit/9b349b77adb46425be15e386ef38f31061be3ca9), authored 2026-10-14 19:44:44 UTC.
- Repository directory slices: [`2/`](https://github.com/rust-lang/crates.io-index/tree/9b349b77adb46425be15e386ef38f31061be3ca9/2) with **725** two-character package-name entries and [`3/a/`](https://github.com/rust-lang/crates.io-index/tree/9b349b77adb46425be15e386ef38f31061be3ca9/3/a) with **282** three-character names beginning with `a`. **1,007 entries in these two bounded slices**, not all crates.io packages, all GitHub repositories, or all open source.
- Immutable source evidence: [pinned raw directory listing with names and git blob SHAs](../research-notes/issue-15-crates-index-bounded-listing-2026-10-14.json). Directory response observed at about 2026-10-14 19:44:57 UTC via connected GitHub REST. The source URLs are commit-pinned, but HTTP response headers and unmodified raw JSON byte streams were **not** preserved; the evidence record is a reduced API representation whose authenticity has not been independently attested.
- [Prespecified transparent sampling plan](../research-notes/issue-15-sampling-plan-2026-10-14.json) freezes 25 names from each slice (**50 package leads**), ordered by SHA-256 of `seed|pkg:cargo/<name>`. The seed is fixed and plainly disclosed, **not a certified random draw** nor evidence of a prospective preregistration. Inclusion among the two slices under a hypothetical exchangeable independently randomized seed would be 25/725 and 25/282 respectively; because that assumption is unverified, these are only nominal fractions, **not validated population inclusion probabilities/weights**.
- No outcome, downstream adoption, GitHub Trending rank or future-reuse signal enters the selection. Name-directory slices are a **structural convenience frame** strongly biased toward 2-character packages and 3-character `a*` packages; even unbiased within-slice random selection could not generalize beyond this scope.
- The `1,007` denominator counts package names, **not resolved unique GitHub repository IDs**. Package-to-repo mapping, forks/mirrors, direct/reverse dependencies, language/project type, package version and creation-year strata still require separate authenticated source snapshots. The pilot is Rust registry-only: no claims of language-balanced or mature/low-star coverage yet.
- **Plan timing (open methods point):** the sampling plan's `declared_at_utc` is 2026-10-14 19:46:00 UTC, about one minute **after** the directory listing was observed (about 19:44:57 UTC). The seed was therefore fixed while the frame was already visible, and nothing here shows that the seed or quotas were chosen blind to the listed names. Treat the 50 leads as a convenience pilot only; confirmatory use needs a fresh seed from an independently verified ceremony declared before the frame is observed.
- **Source data rights (open methods point):** `rust-lang/crates.io-index` has no licence file at the pinned commit's repository root, and the GitHub repository API reported `license: null` when checked on 2026-10-15. Redistribution terms for the committed listing (package names and git blob SHAs) have not been reviewed. A data-rights review is still pending and is not established by this PR.
- License, security, release-time and human task-fit judgments are unknown. **50 leads are not 50 validated task–component pairs**; no empirical missed-by-Trending reuse estimate exists.

## Reproduce without downloading packages

```bash
python -m trending_study.quiet_reuse_registry select \
  --manifest research-notes/issue-15-crates-index-bounded-listing-2026-10-14.json \
  --plan research-notes/issue-15-sampling-plan-2026-10-14.json \
  --output /tmp/issue15-registry-selection.json
python -m unittest tests.test_quiet_reuse_registry -v
python -m unittest discover -s tests -v
```

The CLI is **offline**, standard-library only and write-once: it fails rather than overwriting `--output`. It validates the source's declared shape, within-slice uniqueness and recomputes each directory's Git tree-object SHA-1 from the listed names and blob SHAs (so an edited, dropped or added entry fails), but cannot verify GitHub-hosted data itself. The result is a **selected package lead queue** with repository IDs, project categories and fit all *null/unknown*. The existing `quiet_reuse_frame.select` requires independently resolved positive numeric repository IDs and must **not** be fed guessed IDs.

## Finish empirical acceptance without selection on success

1. **Source QA:** two qualified source reviewers compare all 1,007 package names and blob IDs against the exact pinned Git commit/tree; independently authenticate observation time, source terms and the permitted data redistribution. Record every missing/rejected item and publication decision. The recorded two slices happened to contain 1,007 entries; they were selected for a small bounded feasibility illustration, not shown to be a scientifically representative stratum.
2. **Broader frozen frame:** prospectively choose an admissible multi-ecosystem package/dependency population before outcomes (for example public PyPI, npm and crates.io metadata with explicit access approvals). Include small/medium, old, quiet and high-attention projects by **pre-baseline** project-type, language, year and visibility strata. Keep exact registry version, package URL, source URL, GitHub numeric repository ID, mapping confidence, duplicate/package-family accounting, snapshot date and all exclusion reasons. Retain unavailable mappings as missing, never silently replace them.
3. **Seed and inclusion:** preregister approved baseline, units, all strata, frame-denominator derivation, sampling probabilities including multi-package repositories, and a seed-generation ceremony verified independent of adoption and outcomes. If source coverage cannot be audited, report narrow descriptive inference only; do not claim population weights.
4. **Independent tasks:** independently recruit/freeze a task frame (including tasks with no known solution), timestamps, specification and hidden acceptance SHA-256 *before* candidate search. Enforce tasks' baseline dates and versions; avoid inspecting adoption/reuse to select easy positives.
5. **Pair queue and adjudication:** `prepare_pair_packet(selection, tasks, nominations, manifest, plan)` re-derives the complete selection from the original manifest and plan before accepting selected package leads. The `prepare-pairs` CLI requires `--manifest` and `--plan` alongside `--selection`; see the [packet integrity contract](QUIET_REUSE_REGISTRY_PAIR_INTEGRITY.md) for the interface correction and preserved output fields. Two real independent, appropriately consented human evaluators annotate fit, functional tests, license, supply-chain security and pre-task availability; adjudicate disagreements with a third person and preserve all negatives, nulls, installation failures and excluded/unavailable pairs. `audit_pair_reviews(packet, review_a, review_b, manifest, plan)` (CLI `audit-pairs` with `--manifest` and `--plan`) re-binds the packet to the original frame and checks declared structure only, **not human identity** or external test provenance; even its `concordant_provisional_fit` count is **not scientific acceptance**.
6. **Trend-only omission pilot:** after legal Trending observation access is granted, compare the pinned *observed* Trending surfaces and this source frame over truly matching dates, windows and identities, including an explicit unobserved/unknown category. Absence from the observed surface is **not** proof of never Trending. Evaluate at least 50 genuinely adjudicated task–component pairs for feasibility, not 50 positive outcomes, and report the conditional miss fraction with finite-frame and source-coverage caveats.
7. **Research decisions:** independent ethics/access, seed, eligibility, task and source reviewers sign a dated protocol amendment. Until then, **issue #15 remains open**; neither this PR nor green CI can complete empirical acceptance.

## Practical maintainers' lessons (design recommendations, not effect estimates)

For infrastructure and reusable libraries, add registry package identity, supported versions and canonical repository links; document a runnable task-driven integration and versioned acceptance tests. Keep project discoverability independent of social attention (stars/Trending), and disclose dependency-license/security verification. Test these interventions with real outsider installations and downstream integration evidence before claiming they improve adoption or sustainability. See [maintainer handbook](PRACTICAL_REPOSITORY_GROWTH_AND_REUSE_2027.md).
