## Practical lessons for this and other repositories

- Split every task into a **software finish line** (exact input/edge-case contract + regression tests + CI + code review) and an **evidence finish line** (consent/rights + independent gold judgment + prospective denominator + substantive replication). Close only when its own promised finish line actually completes.
- For Claude Code, start with the existing smallest module and design a negative test first. In this run, reusing three pre-existing URL/time validators was more reviewable than introducing competing parsers.
- Protect **untrusted URL source strings before normalization**, including dot/host ambiguity, numeric IPv4 aliases, whitespace/DEL and raw meaning-bearing query spellings. Lexical validation does not create a safe network client.
- Test **full exception tracebacks** for privacy, including nested causes. A synthetic test can itself leak markers when modern Python prints the literal source call; pass sentinel strings through runtime variables.
- Never delete branches based on merged-PR labels alone; verify live SHA, independent lineage/PR state, archive tag immutability, SHA-leased deletion and restoration capability.
- Prefer practical user value: independent working-task completion, stable reuse, secure licences, bounded human review and upstream maintenance, and measurable lifecycle effects. Stars, PR counts and “20 closed issues” are not scientific or product success metrics.
