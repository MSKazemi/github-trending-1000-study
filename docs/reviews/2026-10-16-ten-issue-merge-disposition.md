## Practical repository lessons

1. **Use two finish lines:** a source-reviewed, exact-head CI-tested *engineering change* versus an *empirical/scientific acceptance* requiring actual observations, sample denominator, independent raters, rights and reproducibility. Only the former was delivered for four workstreams.
2. **Require tested server-side rules:** four matrix checks cannot prevent unreviewed merges while `main.protected=false` and rulesets are empty. Enable #248 rules and test a deliberately disallowed PR before claiming enforcement.
3. **Preserve no-loss provenance:** never delete a branch only because an old PR merged; keep exact original SHAs and cited docs, tests, negative evidence and protected recovery tags; use SHA-leased deletion only following separate authorized security review.
4. **Do not publish false causal or carbon claims:** synthetic P@K, candidate package checkmarks, hypothetical energy models and self-reported job statuses are not independently observed user success, secure packages, kWh savings or vacancies filled.
5. **For Claude Code:** require a frozen user task with independent acceptance tests, time-box a reuse search, check exact package rights/security, record real review/repair effort and keep all failed tasks. Stop at the first missing evidence gate rather than fabricating progress.
