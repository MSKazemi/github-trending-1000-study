## Practical lessons for other repositories

- Reuse one security-reviewed bounded JSON reader and test **whole** exception cause/context graphs, not just friendly stderr.
- When consent is absent/withdrawn, suppress **derived success labels and outcomes**, not only direct identifiers and work timestamps.
- Merge proposed infrastructure policy files without treating the repository as protected: only a successful **live rejection of a prohibited operation** demonstrates enforced rules.
- Before any destructive repository operation, treat an API's missing nested `head.repo` or changed SHA as **blocked**, not a default assumption of safety.
- Keep synthetic CI and science separate: user value, source rights, independent human trials, real maintainer time and unknown denominators remain open questions.
