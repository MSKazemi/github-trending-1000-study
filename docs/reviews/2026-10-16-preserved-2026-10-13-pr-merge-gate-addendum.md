### Repository enforcement defect and immediate policy

The live `main` branch read returned **`protected=false`** and repository rulesets were empty. Thus green Python jobs exist but **GitHub does not structurally require them for merges**. [P0 issue #254](https://github.com/MSKazemi/github-trending-1000-study/issues/254) requires an administrator to enforce both `test (3.10)` and `test (3.12)`, stale-head handling/merge queue, independent approval, no direct push/force push and negative validation of enforcement. The GitHub connector cannot change these administrative settings. This review manually enforced exact-head CI, but does **not** claim the repository branch rule is configured.

### Standing merge contract for simultaneous agent contributions

1. Refresh PR head/base SHAs, draft status, changed-file manifest and conflicts **immediately before** merge. Avoid trusting cached `mergeable` while other commits advance `main`; use protected/expected-head SHA.
2. Review changed code, externally authored sources, schemas, tests, docs and scientific claims **against latest main**, checking duplicates (same issue, CLI and data file) before introducing parallel APIs.
3. For every code PR, require current-head GitHub Actions success for both Python 3.10 and 3.12; inspect failed/skipped jobs; if the base changed in a material way, re-run relevant tests for the resolved merge result. Tests are necessary, **not sufficient**, for external source quality.
4. Fix known defects and add negative tests before integration. Preserve unique earlier materials as attributed amendments or a reviewed canonical migration; never silently overwrite immutable observations or source manifests.
5. For research reports, distinguish source leads, provider-controlled claims, independently reproduced outcomes and futures hypotheses. If job status, posting time, peer review, actual double coding, privacy/rights or human protocol approval are unverified, keep those assertions conditional and the relevant gate open.
6. Merge with expected head SHA, then verify the resulting branch contents and push CI. An attempted merge that GitHub rejects does **not** count as merged, and no draft should be silently presented as reviewed.

**Useful maintainer lesson for 2027:** Parallel AI-agent PR volume is not productivity. Prefer one tested, reusable canonical implementation plus source-preserving consolidation and measured maintenance effort. Even two green test matrices do not establish real-user value, license/security approval, reuse adoption or lifecycle energy savings.
