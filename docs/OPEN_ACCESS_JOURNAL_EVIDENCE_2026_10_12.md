# Open-access journal evidence for AI coding, reuse, and 2027–2031 scenarios

**Evidence search date:** 2026-10-12. **Status:** targeted, non-systematic reading shortlist, **not** a PRISMA review, meta-analysis, completed PDF-by-PDF extraction, expert endorsement, or empirical result of this repository. **Related:** [issue #55](https://github.com/MSKazemi/github-trending-1000-study/issues/55). Publisher versions and author manuscripts can differ; cite the final version after checking both. Every PDF below is intended as a publicly accessible publisher or author/archive link; accessibility may change.

## Further relevant evidence: deliberately excluded from journal-only seven

- [Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity](https://arxiv.org/pdf/2507.09089) — randomized early-2025 coding productivity preprint; **not** put in the journal-only list; narrow selected task/developer population.
- [More Code, Less Reuse](https://doi.org/10.1145/3793302.3793622) — conference/workshop publication; distinct evidence grade.
- [The SPACE of Developer Productivity](https://doi.org/10.1145/3454122.3454124) — influential multidimensional framework in ACM Queue; distinct from controlled effect evidence.
- [DORA 2025](https://research.google/pubs/dora-2025-state-of-ai-assisted-software-development-report/) and [DORA interpretation, 2026](https://dora.dev/insights/balancing-ai-tensions/) — organizational survey/report, not peer-reviewed experiments.
- [2026 Stack Overflow named agent results](https://survey.stackoverflow.co/2026/ai/data/ai-code-agent) and [survey methods](https://survey.stackoverflow.co/2026/methodology) — respondent reports with opt-in selection and multiple answers; not world market share.
- [GitHub Octoverse 2025](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/), [official Codex 2025 launch](https://openai.com/index/introducing-codex/), [Claude Code release](https://www.anthropic.com/news/claude-3-7-sonnet), [GitHub coding-agent announcement](https://github.blog/changelog/2025-05-19-github-copilot-coding-agent-in-public-preview/) — platform descriptions and chronology only.
- [IEA Energy and AI](https://www.iea.org/reports/energy-and-ai) and [SCI for AI](https://greensoftware.foundation/standards/sci-ai/) — energy-system scenarios and measurement standard, respectively, **not** direct evidence that reuse saves carbon.

## What to extract from each full PDF (not yet completed)

- Bibliography: DOI, version, venue, publication and OA license, archive URL, downloaded PDF checksum, access check date.
- Methods: research question; study design; population/frame; sample size; period; actual exposure definition; comparator/control; preregistration; independent outcome validation.
- Result: original effect and uncertainty **only after reading tables/methods**, denominator, unit, statistical assumptions, conflicts, missingness.
- Limitations: representativeness, causality, agent attribution, developer experience, task mix, leakage, tool/version drift, security/license, reviewer effort, energy boundaries.
- Translation: exact applicability to *this* repository; one low-risk intervention, 30/90-day test, guardrail, falsification/rollback threshold; do not fabricate growth/energy gains.

## 2027–2031 conditional outlook: scenarios, not predictions

| Hypothesis | Observable signal | What would weaken/refute | Reusable response now |
|---|---|---|---|
| Agents automate more end-to-end issue/PR workflows. | Opt-in agent workflow traces, independent task resolution with 30/90d regressions. | Low reliable integration, expensive reviews, model drift. | Task specifications, independent tests, explicit human gates. |
| Generated code increases faster than maintainer attention. | Review minutes/accepted task, rework, unreviewed PR age. | Reviewer load and quality improve proportional to agent output. | Narrow PRs, reproduction instructions, documented support boundaries. |
| Search becomes task-to-component integration rather than stars-based retrieval. | Held-out task integration success and time/cost across search systems. | Existing tools beat proposed index at lower cost. | Small independent reuse gold set; include old/niche alternatives. |
| Provenance, permission and compatibility become decisive. | Package provenance/OSV/license failures in candidate screening. | Candidate verification cost outweighs observed safety benefit. | Pin versions, SPDX/license reviews, security checks and provenance. |
| Lower per-call compute cost may coexist with higher total demand. | Energy per *accepted task* AND total workloads, CI, serving and runtime horizon. | Both totals and intensity decline under comparable boundaries. | Calibrate local/CI energy; label provider inference unknown. |
| Executable research artifacts become differentiation. | Newcomer success and verified independent citations/integrations. | Quickstarts improve attention only, not real use. | Reproducible demo, CI, benchmark fixture, provenance, short API example. |

No named-company roadmap is guaranteed; public product launch dates are not adoption measures. Quarterly update with direct company announcements, audited developer surveys, DORA/independent experiments and peer-reviewed research; record contradictions.

## Direct maintainer priorities

1. For each repo, publish **what user task it solves** and a reproducible 5-minute quickstart verified by someone other than the author.
2. Search existing code (including older, low-star projects) before generating: task fit → SPDX rights → vulnerabilities/provenance → smallest patch/upstream contribution versus rewrite.
3. Add pinned demo fixtures, versioned APIs, license/security/update policy and narrowly scoped AGENTS.md with independent tests; avoid claiming these mechanically raise stars.
4. Measure externally reproducible install/run success, independent integration/repeat usage and 30/90-day defect/review burden; preserve missing values.
5. Use the paired observational Trending/quiet-repo frame plus separately approved opt-in randomized human×agent reuse-first study described in the existing protocol; don't assert results before data collection.
6. Do **not** claim green benefits from fewer generated lines or tokens; study equivalent functional output and lifecycle cost.
