# Adaptive five-year research and engineering roadmap (2027–2031)

**Date authored:** 2026-10-11. **Status:** conditional multi-year plan; **NOT** an active funded program, external consortium, data-collection commitment, or an assured publication schedule. Calendar milestones may move when ethics/platform permissions, sampling yield or funding is insufficient. Short-term 2026 pilot is only the prerequisite.

## Invariant north-star and boundaries
The enduring outcome is **independent verified useful work and accessible reusable code per total lifecycle cost**, not generated-code volume, star velocity, AGENTS.md presence or a universal carbon/token coefficient. Keep independent functional/supply-chain safety gates; report applicability by project type, ecosystem, age and risk. A successful niche, scientific or educational artifact can be useful without high adoption.

We define success as **four separately measured dimensions**:
1. User/task effectiveness and reliability, within comparable risks/tasks.
2. Reusable candidate discovery, audited integration and independent repeated adoption.
3. Complete human+upstream support cost, token/billing and 30/90/180d technical debt.
4. Bounded energy/carbon/water/hardware impact for equivalent work and service life (partial scopes clearly labeled).

Do not collapse all four into a single arbitrary benchmark score.

Years are **research waves, not invented observed data**. Absolute counts for experimental tasks/repositories remain provisional until a pilot-derived power analysis, resources and availability check.

## Quarterly operating system (2027 onward)
- **Every quarter:** source/version and dataset coverage audit; changes in model versions and official agent identity attribution; registered RQs versus actual outcomes; publish nulls, attrition and bounded confidence; reevaluate stop rules, research ethics and platform access.
- **Every six months:** refresh task/candidate gold set with *new temporal holdout tasks* to resist memorization; validate assessor agreement; re-estimate agent treatment heterogeneity; review adoption metrics source definitions and privacy.
- **Every year:** integrate exact new standards/registries/tooling as appropriate, audit conflicts of interest, conduct independent replication when feasible, revisit environmental assumptions and add year-stamped forecast corrections without rewriting original predictions.
- **Within each task:** discover existing code first within a predeclared time budget; verify task/license/security/maintenance; choose reuse/upstream/compose/fresh build/do nothing; record actual outcome and cost.

## Annual research claims and publication separation
**Study A:** ecosystem observability: GitHub Trending vs independent component reuse / old public projects. Observational; use explicit candidate frame, avoid causal claims from rank.

**Study B:** coding-agent adoption and workflow effectiveness. Adopted traces are incomplete; direct opt-in logs and assigned workflow experiments for causality. Report task selection, assignment and total human time.

**Study C:** lifecycle green reuse. Requires quality-equivalent alternatives plus measured energy or credible calibrated estimates and provider unknown ranges. Comparative carbon *claims* conditional on full boundaries; allow non-carbon results as valid output.

**Study D (only when justified):** evidence-based retrieval/recommendation tool, its trust model, indexing cost and user adoption vs incumbent retrieval. It is a *possible product*, not the core hypothesis.

Plan separate manuscripts/replication packages rather than one unwieldy study and never publish a green marketing claim based only on token count or an AI-created dependency suggestion.

## Allocation principles for lean and larger programs
A minimal solo version is possible for method design, public pilot capture (subject to access policy), synthetic tests, and small blinded gold labeling. Controlled multi-developer experiments, independent assessors, provider-calibrated LCA and field deployments **require funded collaborators, permission and realistic time**. Don't claim feasibility until these resources exist.

A reasonable **planning heuristic**, not a scientific allocation optimum: concentrate first effort on ground-truth generation and data rights, then reproducible tooling, then independent validation, and **only last** community/product polish. Stop adding features when evidence collection is blocked.

## Technology drift adaptation
- Preserve task, evaluation and acceptance contract independent of the proprietary model; record tool name, exact model/version, permissions, code and source version, price/billing semantics and time.
- Maintain frozen 2027 benchmark panel for longitudinal historical comparison **and** new 2028–2031 challenge panels. Never interpret a newer model's gain on easier newer tasks as a pure capability increase.
- Model quality, token efficiency and legal access may change faster than our cohort followup. Report agent-version × task-type interactions; separate systems-level cost from model inference.
- If future agents can inspect all codebases perfectly, evaluate verification/security/governance/cost instead of continuing obsolete keyword discovery metrics. If proprietary platforms block observation, rely on consented logs and bounded scope.
- Update 2026/2027 claims rather than claiming all future tools share the early agent failure rates.

## Go/no-go gates (sequence is binding for strong scientific claims)
G0 Rights/ethics/measurement boundaries cleared → G1 gold task labeling has acceptable agreement and verifiable evidence → G2 registered experiment/power feasible → G3 randomized comparison with negative/failure cases → G4 30/90/180-day maintainability and environmental uncertainty audit → G5 external replication; **only then** issue generalized recommendations or scale a search product.

**No assumption that all gates will be completed by 2027.** If one blocks, publish the limitation and stop rather than moving unsupported conclusions forward.
